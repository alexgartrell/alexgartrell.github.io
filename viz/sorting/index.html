Sorting race

Six algorithms get the same shuffled bars and the same clock. Every comparison or write costs one tick. Who finishes first?

Ticks 0 Same bars, same clock. Press start.
    Input

    Space start/pause · S step · R reshuffle

    How it works

    Bubble, insertion and selection sort compare items that are close together or scan the whole remainder, so on n items they need about n²/2 steps. Insertion and bubble sort are adaptive, though: try Nearly sorted and they finish almost at once, while selection sort still checks every pair.

    Merge, quick and heap sort split the work into about log₂ n levels of n steps each, roughly n log₂ n in total. For 160 bars that is about 1,200 steps instead of 12,700. No comparison sort can do better in general: there are n! orderings and each comparison at best halves the possibilities, so you need at least log₂ n! ≈ n log₂ n of them.
